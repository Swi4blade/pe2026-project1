# **Спецификация приложения «Система учёта курсовых работ»** 

# **1. Назначение системы** 

Приложение должно заменить текущий процесс сдачи курсовых работ через электронную почту секретарю на единую цифровую платформу, где студенты загружают работы, преподаватели ставят визы, а завкафедрой видит общую картину. 

# **2. Что приложение должно делать** 

Приложение должно принимать от студентов набор файлов (пояснительная записка в Word и дополнительные файлы по направлению) и сохранять их в локальной сети университета. 

# **3. Работа с преподавателями** 

Приложение должно автоматически уведомлять научного руководителя о каждой загрузке (включая черновики) в личный кабинет и на корпоративную почту в течение 1 минуты, с указанием ФИО студента и ссылкой на файл. 

# **4. Статусы и визы** 

Приложение должно позволять преподавателю менять статус работы («Требуются доработки», «Проверена», «Сдана») и опционально оставлять отзыв или комментарий к работе. 

# **5. Отчетность для секретаря** 

Приложение должно автоматически формировать отчет в формате Excel для секретаря, который затем отправляется в деканат. Excel остается рабочим документом в учебном процессе. 

# **6. Фильтрация и разграничение доступа** 

Приложение должно фильтровать работы и уведомления по направлениям обучения (из-за разных дедлайнов) и показывать преподавателю только тех студентов, за которыми он закреплен. 

# **7. Просроченные работы** 

Приложение должно отслеживать работы, сданные после дедлайна, и передавать решение об их принятии преподавателю (система не блокирует загрузку автоматически). 

# **8. Хранение и безопасность** 

Приложение должно хранить все защищенные работы исключительно на локальных сетевых ресурсах университета, без выхода во внешние облачные сервисы. 

# **9. Интеграция** 

В идеале приложение должно быть интегрировано в существующую инфраструктуру университета (в общий сайт) для единого стиля и удобной авторизации, а не быть отдельным сервисом, не связанным с вузом. 

# **10.Границы системы** 

Приложение не должно проверять работы на антиплагиат, не проверять названия и объем работ, а также не блокировать загрузку после дедлайна автоматически. 

# **11.Пользователи системы** 

Основные пользователи: студенты (загружают работы), научные руководители (проверяют и ставят визы), секретарь (формирует отчеты), заведующий кафедрой (видит общую картину). 

# **12.Ожидаемый результат** 

Заказчик хочет получить прозрачный процесс сдачи курсовых работ: без потери писем, с автоматическими уведомлениями, четкими статусами и готовой отчетностью для деканата.

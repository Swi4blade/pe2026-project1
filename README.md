# Система учёта курсовых работ

Учебный проект по дисциплине «Программная инженерия» (версия 0). Студенты сдают курсовые работы не по электронной почте секретарю, а через единую платформу кафедры. Репозиторий содержит проектную документацию: спецификацию, бэклог и глоссарий.

## О системе

Система заменяет текущий процесс сдачи курсовых через почту. В ней:

- студенты загружают пояснительную записку (Word) и дополнительные файлы по направлению;
- научный руководитель автоматически получает уведомление о каждой загрузке, включая черновики, в личный кабинет и на корпоративную почту в течение 1 минуты;
- руководитель меняет статус работы («Требуются доработки», «Проверена», «Сдана») и может оставить необязательный комментарий;
- работы, сданные после дедлайна, помечаются как просроченные, а решение об их принятии остаётся за руководителем;
- секретарь получает автоматический отчёт в формате Excel, который затем отправляется в деканат;
- работы и уведомления фильтруются по направлениям, а руководитель видит только закреплённых за ним студентов;
- все файлы хранятся только на локальных ресурсах университета, без внешних облачных сервисов.

### Пользователи

| Роль | Что делает |
|---|---|
| Студент | Загружает работы и смотрит их статус |
| Научный руководитель | Проверяет работы, ставит статусы, принимает или отклоняет просроченные |
| Секретарь | Формирует отчёты для деканата |
| Заведующий кафедрой | Видит общую картину по работам |

### Вне рамок

Система не проверяет работы на антиплагиат, не проверяет названия и объём работ и не блокирует загрузку после дедлайна автоматически.

## Устройство репозитория

| Файл | Что содержит |
|---|---|
| `specification.md` | Спецификация системы: назначение, функции, статусы, отчётность, фильтрация и доступ, просроченные работы, хранение и безопасность, интеграция, границы системы, пользователи, ожидаемый результат |
| `backlog.md` | Бэклог из элементов Б1–Б13 (Б10 разделён на Б10.1–Б10.3): приоритеты MoSCoW, зависимости и оценка в часах |
| `glossary.md` | Термины предметной области: уведомления о загрузке, статус работы, виза, дедлайн, сдача работы |

## Бэклог

Бэклог описывает постепенное создание продукта: каждый элемент можно выполнить целиком и показать заказчику.

| Приоритет | Элементы |
|---|---|
| Must | Б1–Б7, Б10.1–Б10.3 |
| Should | Б8, Б9 |
| Could | Б11, Б12, Б13 |

Оценка в `backlog.md` задана диапазонами и включает только время на написание кода. Возможные проблемы при выполнении и время на проверку заказчиком не учитываются. Общая оценка: 44–63 часа.

## Правила работы

- Изменения в `main` напрямую не вносятся: работаем через ветку и pull request.
- Заголовок и описание PR обязаны говорить, какую задачу решает изменение.
- Замечание в ревью указывает на конкретную строку и на то, что именно неясно или с чем рассогласовано.
